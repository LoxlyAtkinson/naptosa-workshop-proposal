# Experience acceptance contract: NAPTOSA proposal scroll rebuild

## Current Goal

Rebuild the existing public proposal page into an interactive, visual, scroll-led HTML proposal and publish it at the same GitHub Pages URL. Create the hero video using Higgsfield.

## Current Phase

Asset creation, implementation, then browser verification and publication.

## Scope and criteria

C1 Preserve approved business meaning, existing proposal details, accessible quotation PDF, and all existing entry routes/download destinations.
C2 Hero footage is generated through Higgsfield, silent, scroll scrubbed, with a poster fallback; reduced-motion visitors receive a static usable hero.
C3 Use at least four distinct scroll device families and do not repeat a device family in adjacent acts. Keep a persistent right-side section navigation on desktop and an accessible non-obstructive mobile equivalent.
C4 Every section/control in the original page remains covered and purposeful: Overview, Network, Scope, Workshop schedule, Data choices, Official quotation, Monthly services, Training, Delivery and terms, Acceptance, and PDF download.
C5 Preserve visible original price versus offered price treatment, only show a discount where the figure changes, and keep offered rates/totals clearly emphasized in yellow. Keep Western Cape's existing builds and monthly charges outside new totals.
C6 Explain the shared Western Cape database assumption and the rationale for dedicated encrypted data in a diagram before monthly figures. Keep the offered R499 / environment prominent.
C7 Verify navigation, PDF download, video seek, chapter links, keyboard operation, no horizontal overflow, and reduced-motion behavior in real desktop and mobile browser viewports. Capture and inspect final evidence after the last source edit.
C8 Record browser route, viewport, state, revision, expected/actual outcomes, console/network errors, and screenshots. Keep raw independent review if obtained; do not self-assign independent acceptance.
